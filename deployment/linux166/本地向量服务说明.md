## 方案与适用范围

Embedding 可以在本机部署，不必购买厂商服务。本环境采用 Ollama 的 BGE-M3 模型生成知识库向量，使用 CPU 推理。聊天模型继续使用原有配置，两者独立。

| 项目 | 当前配置 |
| --- | --- |
| 服务 | `coze-embedding.service`，开机自启 |
| 运行账号 | 无登录权限的 `coze-embedding` 系统账号 |
| 运行时 | Ollama `v0.40.16`，仅安装 CPU 组件 |
| 权重 | BGE-M3 F16，约 1.16 GB，1024 维 |
| 服务器资源 | 16 核 CPU，系统可见内存约 20.3 GiB |
| Coze 使用的别名 | `bge-m3-cpu`，复用原权重，设置 `num_thread=8` |
| 监听地址 | `http://172.18.0.1:11434`，Docker 内部网关地址 |
| CPU / 内存上限 | 8 核 CPU / 6 GiB 内存，内存高水位 5 GiB |
| 并发与批大小 | Ollama 并发 1；Coze Embedding 批大小 8 |
| 模型与运行数据 | `/home/coze/embedding` |
| 公网端口 | 未开放 Embedding 端口 |

BGE-M3 支持中文等多语言及最长 8192 token 输入。部署使用稠密向量；没有启用 BGE-M3 的稀疏向量及多向量能力。模型信息参见 [Ollama 模型页](https://ollama.com/library/bge-m3) 和 [BAAI 模型说明](https://huggingface.co/BAAI/bge-m3)。

本地服务不需要厂商 API Key，也不产生按量调用厂商向量接口的费用；仍消耗本机 CPU、内存、磁盘和电力。需要更快的大批量导入时，可考虑独立 GPU 推理节点或厂商服务，不能按小样本耗时推算整份 Excel 的处理速度。

## 与 Coze 的连接

运行配置位于 `/home/coze/src/coze-studio/docker/.env`，相关非敏感配置为：

```bash
export EMBEDDING_TYPE="ollama"
export EMBEDDING_MAX_BATCH_SIZE="8"
export OLLAMA_EMBEDDING_BASE_URL="http://172.18.0.1:11434"
export OLLAMA_EMBEDDING_MODEL="bge-m3-cpu"
export OLLAMA_EMBEDDING_DIMS="1024"
```

后台“知识库配置”在没有保存独立配置时读取这些环境变量。若以后在后台保存知识库配置，数据库中的配置优先，不应只修改 `.env` 后就认定配置已切换。

服务设置 `OLLAMA_NO_CLOUD=1`。systemd 的网络允许范围仅包含回环地址、Coze Docker 网段及本机地址，其他目标被拒绝。166 环境中本机调用可能呈现为 `192.168.1.166` 源地址，因此允许列表中显式加入该地址。

SELinux 保持 `Enforcing`。运行时、二进制、共享库和模型分别设置持久的 `usr_t`、`bin_t`、`lib_t`、`var_lib_t` 文件标签，没有通过关闭 SELinux 来启动服务。

## 本次故障与修复

用户上传“浙江省医疗档案”表格时，初始故障为：

```text
code=105000004
[slices2Columns] embed failed, [Ark] CreateEmbeddings error
can't fetch endpoint sts token without endpoint
```

实际运行配置选择了 Ark，但向量模型名称、Base URL 和 API Key 均未设置。文件已上传，失败发生在后续生成向量及写入搜索索引时，单独配置聊天模型不能补齐 Embedding 配置。

排查重试链路还发现以下问题，已补充源码修复及专项测试：

1. 解析结果写入 JSON 缓存后，表格列数据恢复为通用对象，丢失原有类型。现在从原始 JSON 字节恢复表头、列数据、创建人 ID 和空表头标记，避免 64 位 ID 经浮点数转换丢失精度。
2. 表格入库前缺少空数据检查，会触发数组越界。现在返回可定位的错误，避免异常被掩盖。
3. 重新处理接口没有工作表和行范围参数，不能用默认零值覆盖原先的工作表、表头和起始行选择。现在保留这些原始设置。
4. GORM 结构体更新会忽略空字符串，导致重试时旧错误无法清除。状态更新改为显式写入这些字段。
5. 长任务超过 NSQ 默认消息超时会重新入队。处理器现在每 20 秒续期消息；166 的 NSQD 消息超时为 120 秒、最长处理窗口为 24 小时。

本次失败任务原先留下一个 2048 维空向量索引。先备份索引结构，并使用普通统计和强一致性计数两次确认 0 行，再仅重建该空索引，使其匹配 1024 维模型。没有清空其他知识库或删除用户上传文件。

**以后更换向量模型时，即使维度相同，也要按新的模型重新生成已有知识的向量，不能把不同模型的向量直接混用。**

原运行 Compose、受限 `.env` 和空索引结构备份位于 `/home/coze/ops/embedding-backup-path` 指向的目录，权限仅限运维账号。`.env` 不复制到 Git 仓库或本说明中。

后端和队列配置回退前应先确认是否有正在处理的导入任务。回退到最初版本会恢复未配置 Embedding 的状态，也会失去本次的表格重试和长任务修复；更换回向量模型时需要配套恢复或重建索引，不应直接覆盖数据库或清空全部向量数据。

服务单元、非敏感运行参数和构建脚本随仓库文档一同保存。升级前校验新运行时与模型来源，在独立构建目录验证后再切换，模型、缓存和临时文件继续放在 `/home`，避免占满系统分区。

后端构建使用 [build-knowledge-server.sh](scripts/build-knowledge-server.sh)，服务单元见 [coze-embedding.service](scripts/coze-embedding.service)。重启后的登录弹窗原因与修复见[重启后访问修复说明](重启后访问修复说明.md)。
