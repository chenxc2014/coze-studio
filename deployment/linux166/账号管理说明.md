# Coze Studio 统一账号管理与运维说明

更新日期：2026-11-10。服务器：`ssh linux166`。基线：`v0.5.1`，增加本仓库的账号管理模块。

## 入口与使用方式

正式公网入口为 `https://ai.yaoxiaoyi.com/agent/admin/#account-management`，登录页为 `https://ai.yaoxiaoyi.com/agent/sign`。子路径访问已完成浏览器验收，详情见[子路径访问说明](子路径访问说明.md)。

平台入口为 `http://192.168.1.166:8888`。管理员登录后，打开管理后台中的“配置管理 → 账号管理”，或直接访问：

`http://192.168.1.166:8888/admin/#account-management`

该页面面向平台管理员，统一维护全部未删除的平台账号。平台管理员可以管理平台模型和基础配置，请仅授予可信人员。

## 支持的操作

| 操作 | 具体行为 |
| --- | --- |
| 查询账号 | 按邮箱、姓名、用户名搜索；按启停状态及管理员身份筛选；每页 20 条 |
| 新增账号 | 填写邮箱、姓名、初始密码和角色；同时创建个人空间；无需开放公开注册 |
| 编辑账号 | 修改姓名；邮箱作为登录标识保持只读 |
| 重置密码 | 设置 12 至 128 个字符的新密码，清除该账号的网页会话 |
| 停用账号 | 阻止新登录、清除网页会话，并在每次 OpenAPI 鉴权时拦截该账号的 API Token |
| 启用账号 | 恢复登录资格，使用人需要重新登录；原 API Token 恢复可用，但仍受原有有效期和平台规则约束 |
| 管理员身份 | 授予或取消管理员身份，与“基础配置 → 管理员邮箱”使用同一份配置 |

重置密码不会撤销 API Token。如需同时阻止该账号的外部调用，应停用账号；如需永久撤销某个 Token，应在平台原有 API Token 管理入口删除对应 Token。

账号停用会保留智能体、工作流、知识库和个人空间。当前没有删除账号、批量导入、组织部门或企业 SSO 功能；管理员身份也不等同于查看所有人的私有空间内容权限。

## 推荐维护流程

1. 保持公开注册关闭，由管理员统一新增账号。
2. 创建账号时使用有效邮箱和姓名，设置足够长的初始密码，通过安全渠道交付给使用人。
3. 使用人登录后，在头像菜单的账号设置中修改自己的密码。
4. 人员离职或暂停使用时，先停用账号，再按业务需要安排其智能体和知识库的后续维护。
5. 交接管理员时，先新增并启用接任者，授予管理员身份，确认接任者可登录管理后台，再由接任者取消原管理员身份或停用原账号。

平台不会通过邮件自动发送初始密码，也未实现强制首次登录改密。管理员应通过已有安全渠道通知使用人。

## 权限与保护规则

- 所有管理接口都校验登录会话和管理员身份；账号页面同时在应用层再次验证当前账号状态和角色。
- 当前登录账号不能停用自己，也不能取消自己的管理员身份。
- 基础配置页不能移除当前登录人的管理员邮箱，不能把管理员名单置空。
- 管理写操作锁定同一条基础配置记录，在同一事务中保存变更并校验至少保留一位已启用管理员，防止并发操作绕过保护。
- 停用校验覆盖新登录、已有网页会话和已有 API Token；已开始执行的请求或流式连接不会被主动中断，后续请求会被拦截。
- 写接口只接受与平台同源的 JSON 请求，拒绝跨站表单与缺少 Origin 的写请求。
- 返回字段不包含密码、密码散列、会话密钥和 API Token；用户 ID 使用字符串传输，避免浏览器数字精度损失。
- 新增、资料变更、密码重置、启停、角色变更和基础配置保存均记录操作人、目标账号、动作和时间，不保存明文密码。

初次安装其他环境时，应先按原部署流程初始化管理员及基础配置。本模块不提供管理员名单为空时的开放注册或越权初始化入口。

## 数据存储与备份

用户身份仍保存在原 `user` 表，密码沿用原有 Argon2id 算法。未新增字段，也未把删除状态或邮箱验证字段用作停用标记。

| 数据 | 存放位置 |
| --- | --- |
| 管理员邮箱 | `kv_entries`，namespace 为 `kv_config_ns`，key 为 `basic_config` |
| 账号启停状态 | `kv_entries`，namespace 为 `user_account_controls`，key 为用户 ID |
| 操作记录 | `kv_entries`，namespace 为 `user_account_audit`，key 为随机 UUID |

旧账号没有启停记录时，默认启用。账号操作记录目前不提供独立查询页面；运维可以只读查询对应 namespace，数据随现有 MySQL 元数据备份一同备份。操作记录不自动清理，应随数据库容量监控评估归档周期。

服务器原有每日数据库备份、日志上限和容量告警继续生效。编译工具、依赖、缓存、临时目录和产物均放在 `/home/coze`；它们属于构建数据，不应混入数据库或对象文件目录。首次构建会额外使用数 GB 空间，后续复用缓存。

## 部署与回退

采用定制后端镜像替换原官方后端二进制，保留官方运行时环境及原前端镜像。运行配置和模型凭据不通过源码覆盖；后台静态文件仍从原 `backend/conf` 挂载目录读取。

部署前创建数据库备份，并在 `/home/coze/backups/account-management-时间戳` 保存原 Compose 和管理页面。最近一次回退目录记录在 `/home/coze/ops/account-management-backup-path`。回退仅切换镜像及静态页面，不恢复旧数据库，避免覆盖部署后的正常业务数据。

需要回退时，由运维确认上述目录后恢复其中的 `compose.json` 到运行的 `docker/docker-compose.deploy.json`，恢复 `admin` 目录内容，然后执行：

```bash
/home/coze/ops/compose.sh up -d --no-deps coze-server
docker exec coze-web nginx -t
docker exec coze-web nginx -s reload
```

回到原版后端后，原版不会读取新增的停用标记。因此原版镜像回退仅用于应急恢复，不应用于仍需要强制停用控制的长期运行环境。
