# API 表格导入使用与运维说明

更新日期：2026-11-12。平台入口：`https://ai.yaoxiaoyi.com/agent/`。

## 使用方式

1. 在资源库创建知识库，选择“表格格式”，导入类型选择“API”，点击“创建并导入”。
2. 在“新增 API”步骤添加 HTTP 或 HTTPS URL，支持内网地址和自定义端口，选择不自动更新，或每 1、3、7、30 天更新。
3. 点击“抓取并保存”，平台后端以 GET 请求读取 JSON，并显示可导入行数。
4. 进入“表结构配置”，调整列名、字段类型和需要建立语义索引的列。至少选择一列语义索引；医疗机构场景建议选择机构名称和详细地址。
5. 预览内容后进入数据处理，待切片完成。完成后把知识库绑定到智能体，并启用知识库自动检索。

这是把 API 数据导入为平台知识库。智能体提问时检索已导入的数据；实时业务查询、分页业务 API、自定义请求头鉴权不属于本次导入功能。

## 没有业务 API 时的示例

URL 弹窗提供“使用示例 API（虚构测试数据）”，会填入：

`https://ai.yaoxiaoyi.com/agent/admin/examples/medical-institutions.json`

该公开 HTTPS 地址返回三条完全虚构的机构，用于练习配置、导入和智能体检索，不包含客户数据。路径含 `admin` 是因为文件通过现有静态资源目录提供；读取这个示例不需要管理员身份，也不需要登录。

导入后可在仅绑定该示例知识库的智能体中提问：“查询示例区示例街道演示路101号的医疗机构”。业务上线时换成实际数据接口地址。

## 接口数据约定

支持 UTF-8 JSON 对象数组，例如：

```json
[
  {"机构名称":"演示机构（虚构）","市":"示例市","区县":"示例区","详细地址":"示例区演示路101号","联系电话":"000-00000001"}
]
```

也支持 `data`、`rows`、`items`、`list` 包装，最多解包三层；每一层只能有一个符合上述名称的候选数据字段。字段值支持字符串、数字、布尔值和 null，嵌套对象及嵌套数组应由接口先整理为平面字段。

| 项目 | 当前实现 |
| --- | --- |
| 请求 | HTTP 或 HTTPS GET，HTTP 状态必须为 200；允许应用服务器能访问的内网地址 |
| 端口 | 支持接口实际使用的端口，例如 8000、8080、8443 |
| 响应大小 | JSON 和转换后 CSV 均不超过 8 MB |
| 数据规模 | 最多 50000 行、100 列，单个字段值不超过 65535 字节 |
| 空响应 | 空数组拒绝导入或更新，避免意外清空知识表 |
| 翻页 | 单次响应必须提供需要导入的完整数据，不自动遍历接口分页 |
| 鉴权 | 本次不支持自定义 Header、Cookie、POST 请求体或 OAuth |
| 重定向 | 最多三次，目标仍须为 HTTP 或 HTTPS 地址，允许跳转到内网及自定义端口 |
| 抓取超时 | 单次 HTTP 请求最多 30 秒 |

JSON 数字转换为 CSV 时使用原始数字文本，不经过 float64。业务编号、电话、邮编等需要保留格式的字段，建议接口返回字符串并在表结构中选择 String。每次抓取使用相同的字段排序，缺失值补空；字段结构变化会阻止自动覆盖原表。

实现参考[扣子官方表格知识库说明](https://docs.coze.cn/guides_create_table_knowledge)。本平台在官方基础导入流程上增加示例入口、来源状态和手动更新，并将单次响应限制设为 8 MB；官方文档列出的限制为 64 KB，不能据此推断两者的容量相同。

## 更新和失败处理

API 导入的知识表顶部显示来源 URL、自动更新频率、最近成功时间、下次检查时间和错误信息。拥有者可以调整频率或点击“立即更新”。

- 更新频率按上次检查或调整频率后的连续 24 小时计算；后台每分钟检查到期文档，不保证精确到秒。
- 更新采用接口全量数据替换这份知识表，不做追加，不按业务主键合并。手工编辑的内容可能被后续更新覆盖。
- 数据没有变化且原文档已完成时只更新检查状态，不重复切片和生成向量。
- 先完整抓取、检查字段结构并用已配置字段类型试解析；HTTP 错误、JSON 错误、空数据、字段变化或类型不兼容时，保留已完成数据并记录错误。启用自动更新的失败任务约一小时后再试。
- 数据变化且校验通过后，进入现有切片及索引流程；处理期间知识表会显示处理中。Embedding 或索引服务故障仍可能导致处理失败，应排查后重新更新，不能把拉取成功等同于索引成功。
- 同一个文档使用 MySQL 连接级命名锁，避免多个后端实例重复投递同一轮更新。处理中的文档不接受另一轮刷新。
- 更新配置、到期时间、内容摘要和成功时间保存在数据库，服务重启后按持久状态继续检查。

## 存储、权限与容量

文档来源使用 API 类型，配置保存在现有 `knowledge_document.parse_rule.api_source` JSON 中，无需新增数据库表或字段。JSON 转换后的 CSV 放在对象存储 `api-table/<拥有者ID>/<随机ID>.csv`，沿用现有 MinIO 数据分区。

预览配置绑定账号并在 Redis 缓存 24 小时。过期后需要重新抓取；其他账号不能复用这份预览导入。API 来源读取、修改频率和立即更新都校验文档拥有者，写请求要求当前平台同源 JSON 和有效登录态。

抓取由应用服务器执行，使用服务器的网络与域名解析，禁用环境代理。根据本次使用要求，已取消公网 IP、HTTPS 专用协议和固定 443 端口限制；URL 中的查询参数正常传递，`#` 后的片段不参与 HTTP 请求。能否访问以服务器及容器的实际连通性为准，浏览器能访问不代表服务器一定能访问。

API CSV 使用 `/home/coze` 下的对象存储，不写入系统根分区。后台每小时分页清理超过 48 小时且不再被有效文档或在途更新引用的 API CSV，每次最多检查 100 个对象；预览缓存到期后自动失效。这个清理仅针对 API CSV，不清理客户仍在使用的知识文件。持续大量上传时仍须观察对象存储、向量数据和备份容量。

原有容量守卫继续生效：系统分区剩余至少 15 GiB，`/home` 剩余至少 25 GiB，任一分区使用率不得达到 80%。构建、镜像和发布目录均在 `/home/coze`。

## 构建与排障

后端隔离构建：`bash deployment/linux166/scripts/build-api-table-server.sh /home/coze/build/source`。前端沿用 `build-agent-web.sh` 及 `/home/coze/build/subpath-source`，保持 `/agent/` 资源和页面路由。

扩展接口均为 POST，位于 `/api/knowledge/table-api/`：`prepare` 抓取并暂存；`source` 读取来源状态；`schedule` 修改天数；`refresh` 请求立即更新。公网访问这些接口时必须加 `/agent` 前缀。

来源更新报错时先查看知识表顶部的错误和最近成功时间；然后检查接口协议与端口、服务器网络可达性、完整 JSON 响应、字段结构、字段类型和 Embedding/索引服务。不要直接清空客户知识库或重新导入原 19946 行医疗档案来排查本功能。

完整验收结果见同目录 `API表格导入验收.json`，包括临时数据的真实导入、到期更新和智能体自动检索。独立 TypeScript 检查受仓库已有 workspace 声明产物缺失（TS6305）限制；实际 Rush 前端构建、子路径测试与浏览器交互验收分别记录，不能把单包 tsc 当作已全绿。
