任务中心使用与运维说明

部署配置、磁盘规划与日常维护操作。容量和验收状态为原文记录的历史快照。

打开平台 下载 Markdown

更新日期：2026-11-14。平台入口：https://ai.yaoxiaoyi.com/agent/。

本次在 Coze Studio 中新增“任务中心”，同时提供批量任务和异步任务两个页签。入口位于工作空间左侧导航，地址为 /agent/space/{space_id}/tasks。本文适用于本仓库的定制版本。

功能范围

功能 批量任务 异步任务
任务对象 当前空间资源库或应用中已发布的普通工作流 同左
输入 上传 CSV，每行参数执行一次工作流 填写表单或 JSON，每次提交执行一次
执行版本 创建时固定，发布新版本不改变原任务 同左
后台执行 提交后执行，关闭页面继续运行 创建配置后手动提交，可反复执行
结果 逐行详情、原生工作流日志、CSV 导出 每次执行独立记录、历史分页、CSV 导出
操作 取消、重试未成功项、删除整个任务 同左，另有“执行任务”

本次实现采用现有工作流引擎，提供本地可用的任务中心。没有新增云版的“异步任务工作流节点”，没有新增定时执行、回调通知或面向外部调用的任务中心 PAT API。平台原有工作流开放 API 不受此模块替代。

使用批量任务

  1. 在资源库或应用中准备普通工作流，配置开始节点输入参数，发布一个版本。应用内工作流还需要满足原生引擎对应用发布渠道和版本的要求；仅保存草稿不可使用。
  2. 打开任务中心的“批量任务”，点击“创建批量任务”，填写名称、选择工作流及固定版本。
  3. 下载 CSV 模板。保留模板参数名称，将数据填入对应列，每行对应一次执行。文本中含逗号、换行或引号时，按标准 CSV 规则转义。
  4. 上传文件。服务端检查编码、列名、必填项、参数类型、行数和文件大小；通过后显示前五行预览。
  5. 选择并行执行数及单条最长运行时间，确认后点击“创建并执行”。模型及插件的实际调用可能产生相应费用。
  6. 在详情中查看进度、逐行结果或错误。执行结束后可导出 CSV，也可重试未成功项。

支持 UTF-8（含 BOM）和 GB18030 编码。整数使用 64 位有符号整数，布尔值填 true 或 false，对象与数组使用 JSON。预览、输入存储及结果原文显示保留大整数，不通过浏览器数值重新序列化。

模板中可选参数列可省略；缺少必填列、未知列、重复列、空数据行或无效参数会被拒绝。没有输入参数的工作流应使用异步任务。

CSV 示例，列名必须与实际工作流参数一致：

address,limit
浣东街道康福路98号,10
"鹿城区藤桥镇,上戍社区",20

使用异步任务

  1. 在“异步任务”页签创建任务，选择已发布的工作流及固定版本。
  2. 创建只保存任务配置，不立即运行。
  3. 点击“执行任务”，按工作流参数填写表单，或切换到 JSON 模式，然后提交后台执行。
  4. 关闭页面不会取消执行。再次打开详情，可查看执行状态和结果。
  5. 同一任务可反复提交，不同提交产生不同执行记录；详情中可按每组 20 条翻阅历史。

异步指页面提交后由服务器后台处理，不要求浏览器持续连接。工作流自身节点的超时、权限和模型、插件配置仍然生效。需要人工交互的中断工作流，应在原工作流编辑器中处理，任务中心不会代替人工回答或自动恢复交互。

状态、取消与重试

状态 含义
未执行 异步任务配置尚未提交过参数
排队中 / 执行中 等待后台调度或正在运行
已完成 本次所有行成功
部分失败 / 失败 存在失败行，可查看具体错误
取消中 / 已取消 停止领取新行，并请求取消正在运行的行
已中断 执行结果无法确认，需要核对后手动处理

取消不能撤销已经完成的第三方操作。重试会创建新执行记录，只复制失败、已中断或已取消的行，保留原行号，成功行不会再次执行。涉及写入、支付、发送等外部副作用时，先核对实际结果再重试。

服务器重启后，尚未开始的行继续排队；重启时正在执行且结果未确认的行标为已中断，不自动重复执行。请求使用唯一标识去重，相同标识和参数重复提交返回原记录；同一标识改用不同参数会被拒绝。

权限与容量限制

空间成员可查看所属空间的任务和结果。只有任务创建者可以执行、取消、重试和删除；其他空间成员不能访问。共享空间中的任务输入、输出应按空间成员可见的信息准备。

项目 当前限制
单个 CSV 最多 1000 行、2 MiB
单条输入 / 输出 16 KiB / 32 KiB
单任务并行行数 批量 1～4 条，异步 1 条
全平台后台调度 同时最多 2 次执行记录，总计最多 8 条工作流调用
单条运行超时 接口允许 10～86400 秒，页面提供 10 分钟、1 小时、6 小时、24 小时
每账号活跃执行 最多 10 次排队、执行中或取消中的执行记录
每账号任务数 最多 200 个
每账号任务数据 输入、输出及错误信息计入 256 MiB 应用配额，排队时预留输出额度

上述配额控制的是应用计量的数据，不等于 MySQL 表、索引或备份的物理磁盘上限。任务中心以数据库保存输入和结果，不额外长期保存上传的 CSV。删除已经结束的整个任务可释放该任务数据；不会自动清理用户历史。超大结果建议由工作流写入文件并返回链接。原生工作流引擎的执行日志仍由其现有机制维护，不计入上述任务表配额。

调度方式与数据表

后台调度运行在 Go 应用进程中，使用受控 goroutine 并发及 MySQL 持久化队列，约每秒检查队列。它不是 crontab，不需要新增系统定时任务。

使用 MySQL 命名锁选出唯一调度者，锁名按数据库隔离。数据库连接丢失后停止领取并取消本调度者的执行；行和执行记录带调度者标识，旧调度者不能覆盖新调度者的结果。应用层执行前重新校验创建者空间权限和工作流归属。

新增的三张表为 taskcenter_tasks、taskcenter_runs、taskcenter_items，分别保存任务配置、执行记录和逐行结果。迁移脚本位于 deployment/linux166/scripts/task-center-schema.sql，只创建独立表，不修改原有知识库、账号和工作流表。应用启动不自动执行 DDL；缺表时仅任务中心返回“尚未初始化”。

首次部署应先按现有备份流程备份数据库，再执行迁移脚本，最后部署后端及前端。重复执行 CREATE TABLE IF NOT EXISTS 不会升级已经存在但结构不同的表；后续结构升级必须单独编写迁移。

日常检查与回退

166 的模型、构建、发布版本和备份继续放在 /home/coze。部署前使用容量守卫，要求系统分区至少剩余 15 GiB、/home 至少剩余 25 GiB，且使用率不高于 80%。运维脚本及包含运行配置的备份仅供服务器管理员读取。

python3 /home/coze/ops/capacity.py --guard
/home/coze/ops/compose.sh ps
docker logs --since 10m coze-server

任务不启动时，依次检查：用户是否有空间权限；任务选择的版本是否存在；三张表是否齐全；应用是否记录调度者失去数据库访问的错误；数据库是否有正在运行的长任务。日志不记录任务中心 HTTP 请求正文，避免 CSV 参数进入接口访问日志；工作流节点自身的日志继续遵循原有行为。

新前端使用独立发布目录，后端使用独立镜像；部署时保留原 Compose 备份和元数据备份。回退应用时使用本次部署生成的 Compose 备份恢复后端镜像和前端挂载，然后仅重建 coze-server、coze-web。先处理仍在运行的任务，避免发布期间产生结果未确认的中断行。

回退应用版本时保留新增任务表及用户数据，不自动删除表，不用旧数据库备份覆盖部署后产生的数据。回退到不含任务中心的版本后，这些任务不会继续被旧应用调度；重新启用新版本时按上述恢复规则处理。

验证记录

功能验收汇总见同目录 任务中心验收.json，包括真实平台回显工作流、两个页签的浏览器操作及清理结果。调度器另外在独立临时 MySQL 数据库验收了取消、请求去重、失败项重试、最多 8 条并发、强制终止后的恢复和不自动重放未确认行；临时库已删除。临时回显工作流不调用模型和插件。

后端新增 CSV 与状态汇总单元测试、工作流桥接与接口包编译检查、前端定向严格 TypeScript 检查和生产构建均通过。新增页面已使用仓库 Prettier 配置格式化。定向 ESLint 检查在 90 秒限制内未完成，未计为通过；未执行全仓库 lint 或全仓库测试。功能验收通过不代表这些静态检查已经完成。
