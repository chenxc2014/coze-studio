地址查询使用与运维说明

部署配置、磁盘规划与日常维护操作。容量和验收状态为原文记录的历史快照。

更新日期：2026-11-11。平台入口：https://ai.yaoxiaoyi.com/agent/。

当前行为

核心场景是创建知识库、绑定到智能体，然后直接在对话中按地址查询医疗机构。智能体自动提取地址条件并从已绑定知识中检索，内部完成必要的分批读取，一次组织回答。用户不需要先打开查询页面，也不需要输入“下一页”来驱动检索。

知识库页面的“地址查询”入口保留，用于人工核对数据、排查筛选条件。该辅助页面仍有分页，分页不会成为智能体对话的使用步骤。

运行镜像：coze-local/server:address-822f8afea1f8。后端二进制 SHA256：822f8afea1f81ced4658f508a9336222f46002faa668d5b2c4187a4cbbc904ad。

生产 Embedding 继续使用 bge-m3-cpu、1024 维、批大小 8。本次地址筛选复用表格知识的结构化数据，直接查询授权范围内的原始表，不需要为地址条件生成查询向量，也没有重建向量索引。

在智能体中使用

  1. 创建或打开表格知识库，确认知识文档处理完成，包含市、区县、地址等可识别字段。
  2. 在智能体中绑定该知识库，选择已配置的聊天模型。
  3. 直接提问，例如“查杭州市西湖区有哪些医疗机构”“查杭州市西湖区文一路有哪些医疗机构”“杭州西湖区的医疗机构有多少”。
  4. 可以继续问“这些机构总共有多少条记录”“改查宁波市海曙区，医疗机构有多少”，系统结合对话理解条件变化。

每个智能体只读取实际绑定、可用的知识文档；新建且字段兼容的表格知识无需再逐份配置文档白名单。明确的标准问法优先本地解析；非标准问法和上下文追问复用该智能体当前选择的聊天模型识别条件，不需要新增模型凭据。地址不明确时先澄清，不根据常识编造省市。

计数使用完整匹配记录数。名单在服务内部每批读取 100 条，当前每个文档最多向聊天模型提供 200 条、16,000 个字符的资料；超出预算时保留完整匹配总数，明确资料只是摘要，不声称已列出完整名单，也不要求用户手工翻页。最终回答长度仍受智能体所选模型的输出上限影响。

名单默认提供机构名称、行政区及地址。问题明确要求电话、联系人或点名其它原始列时，保留相应字段；询问“详细信息”时保留原始字段。字段仅来自知识记录，不由模型补造。匹配总数是记录数，未额外进行机构去重。

本次结构化路径面向医疗机构范围名单及记录计数。医院等级、公立民营、距离、附近等附加条件继续使用原检索链路，不能宣称已经按这些条件完成精确筛选。“医院”可能表示机构类型，不能直接用全部医疗机构数替代医院数。

街道、路段、门牌匹配基于规范化地址文字包含关系，不使用地图坐标或行政边界。同名街道应结合城市、区县；例如“12号”也可能包含在“112号”文字中，不等同于地图门牌解析。

辅助查询页面

在知识库页面右下角点击“地址查询”，空间和知识库随入口带入；选择表格文档，填写市、区县、街道或详细地址，或者输入明确问法后查询。页面显示匹配总数，并支持每页 20、50、100 条及人工翻页。修改条件后须重新查询。

直接入口：https://ai.yaoxiaoyi.com/agent/admin/knowledge-address.html。链接本身不授予知识访问权限，仍需登录和文档权限。

导入中默认不将部分数据当作完整结果；仅在人工页面显式勾选“查看已导入的部分数据”时允许预览，页面持续标记资料不完整。失败、停用、删除文档不能通过这个开关查询。当前浙江知识已完成全部 19,946 行处理。

辅助查询接口

POST /agent/api/knowledge/address/query 复用平台登录会话及知识文档读权限。此接口供人工页面使用；智能体通过内部检索链路取数，无需客户端先调用它。已发布智能体外部聊天 API 沿用原有授权机制，本次真实对话验收使用草稿智能体接口。

字段 类型 说明
document_id 字符串 文档 ID，不能转为 JavaScript Number
filter.province 字符串 可选，省份字段
filter.city 字符串 可选，城市字段
filter.district 字符串 可选，区县字段
filter.address 字符串 可选，街道、路段、详细地址文本
query 字符串 可选，明确的医疗机构地址问法
page / page_size 整数 人工页码 1～10000，每页 1～100 条，字段查询默认 20 条
allow_partial 布尔 默认 false，仅允许预览正在导入的部分数据

成功返回 code=0，data 包含 filter、total、page、page_size、has_more、import_complete、columns、rows。记录 ID 为字符串。无匹配时返回 0 和空列表，不转查其它地区。

匿名请求被拒绝；无文档权限返回 403；非法页码、空条件或条件冲突返回 400。查询值使用参数传递，%、_、引号按普通文字处理。物理表名和列标识符来自受校验的服务器元数据。

配置与源码

  • 地址解析：backend/domain/knowledge/address/query.go。
  • 查询、内部批读取及资料预算：backend/domain/knowledge/service/address_query.go。
  • 智能体模型识别：backend/domain/agent/singleagent/internal/agentflow/address_resolver.go；检索接入位于 node_retriever.go。
  • 权限和路由：backend/application/knowledge/address_query.go、backend/api/handler/coze/knowledge_address.go、backend/api/router/knowledge_address.go。
  • 辅助页面：backend/conf/admin/knowledge-address.html、.js、.css；入口位于原 app-base-path.js，保留 /agent/ 适配。
  • 运行 Compose：/home/coze/src/coze-studio/docker/docker-compose.deploy.json；运维入口：/home/coze/ops/compose.sh。

COZE_ADDRESS_DOCUMENT_IDS 仅保留给非智能体检索调用的试点接管。智能体使用绑定知识自动检索，不依赖此白名单；清空该变量不会关闭智能体路径。若需整体回退该能力，应回退后端版本。

发布与回退

外网运维使用用户指定的免密连接：

ssh -i C:\Users\chenx\.ssh\id_ed25519_chenxc -p 9822 root@cm800.gicp.net

内网原别名 ssh linux166 指向同一主机。外网主机密钥与原内网记录一致，保留严格主机密钥校验；文档不包含私钥内容或账号密码。

在 /home/coze/build/source 独立源码副本构建，先通过容量检查及 Go 专项测试，再制作新镜像；发布前备份元数据和运行配置。本次发布备份：/home/coze/backups/address-query-20261111-221506，其中 compose.json 指向本次发布前版本。

回退时将该备份的 compose.json 恢复到运行 Compose 路径；如同时回退页面资源，从同一备份恢复对应资源。随后执行：

/home/coze/ops/compose.sh up -d --no-deps coze-server
docker exec coze-web nginx -t

保留已发布旧镜像供回退，包括原知识库修复镜像 coze-local/server:knowledge-bcb33908269a。无需删除知识文件或向量。不要用本地公开 Compose 快照覆盖线上私有配置。

构建、镜像、模型、数据都放在 /home/coze，本次没有生产数据库表结构迁移。验收快照系统分区可用 67.62 GiB，数据分区 /home 可用 94.31 GiB。保留版本应按容量计划清理，不执行全局镜像或数据卷清理。
