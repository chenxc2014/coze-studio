地址检索区县字段兼容修复说明

部署配置、磁盘规划与日常维护操作。容量和验收状态为原文记录的历史快照。

打开平台 下载 Markdown

日期：2026-11-26。

平台入口：https://ai.yaoxiaoyi.com/agent/。

问题与原因

智能体“通过地址查询医疗机构详情”在预览与调试中，输入“广东省深圳市南山区南头街道桃园路89号（桃园路与南山大道交汇处）”，返回 Something error:Internal Server Error。新建预览会话也能复现，排除了仅由旧会话消息引起的情况。

对应后端日志为：[NodeRunError] 该表格缺少查询所需的行政区字段。当前绑定的“浙江省医院档案01”使用“区”作为区县列名，而地址检索代码只识别“区县”“区/县”等列名。识别地址后，执行结构化筛选时找不到区县字段，错误传递至智能体运行链路，对外显示通用内部错误。此错误发生在插件执行之前。

修复内容

backend/domain/knowledge/service/address_query.go 的区县字段识别增加“区”“县”两个常用列名，保留原有别名。

查询仍保留省、市、区县、详细地址条件，使用参数化 SQL。没有为了返回结果而删除行政区条件，也没有修改客户表结构或重新切片。查不到目标地址时应返回零匹配记录，后续由智能体结合原有提示词和已配置工具处理。

验证

  • 原问题修复前：新建预览会话约 2.3 秒返回内部错误；日志确认缺少行政区字段。
  • 地址解析包测试通过：go test -p 3 ./domain/knowledge/address。
  • 地址检索服务相关测试通过：go test -p 3 ./domain/knowledge/service -run "TestAddress" -count=1。
  • 新增回归覆盖“区”“县”“区县”“区/县”“区（县）”“区(县)”六种列名，并检查查询库外地址时保留广东省、深圳市、南山区条件。
  • git diff --check 通过。

整个 knowledge/service 包的既有测试依赖本机 127.0.0.1:3306 测试库和 Mockey 编译参数，当前隔离构建环境未配置该测试库，全包测试不能作为通过依据；本次相关地址测试不连接生产数据库，已单独运行通过。

线上使用用户当前有效会话，调用与“预览与调试”一致的接口进行回归，不保存登录凭据：

  • 原深圳地址：约 14.81 秒正常返回结构化 JSON，并出现工具调用与工具响应事件，未再返回 Internal Server Error。这项验证确认运行链路恢复，不代表对联网结果内容作了独立事实核验。
  • “杭州市西湖区有多少家医疗机构”：约 6.02 秒正常返回知识库计数，并提示匹配记录数不等同于去重机构数。
  • 修复版本启动后的错误日志筛查，未发现新的错误。
  • 隔离构建目录 1,098 个受版本控制的 Go 源码及依赖清单文件与本地当前版本摘要一致。
