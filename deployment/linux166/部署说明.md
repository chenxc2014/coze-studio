## 容量控制

- `/home` 剩余小于 25 GiB、系统分区剩余小于 15 GiB，或任一分区使用率达到 80%，容量检查返回失败。
- 服务通过 systemd 启动前执行同样的检查；日常每十五分钟检查一次。
- 当前检查结果：`/home/coze/ops/capacity-latest.json`。检查失败记录在 systemd journal，尚未接入短信、邮件等外部通知。
- 告警不会自动删除业务数据，也不会自动停止正在运行的业务；需在阈值触发时及时处理或扩容。
- 每个容器使用 `local` 日志驱动，单文件 20 MB、保留三份。
- 主机 journal 限制 512 MB，运行时 journal 限制 128 MB。
- MySQL binlog 保留三天，单文件上限 100 MiB；活跃日志与其他数据库文件仍可能增长。
- 单次请求体上限 50 MiB；这是请求限制，不是知识库总容量限制。
- Elasticsearch 堆限制为 512 MiB～1 GiB，各服务配置内存上限。

### 扩容路径

现有 XFS 文件系统不能依赖缩容来重新分配空间。建议在 `/home` 可用空间接近 35 GiB 时开始扩容准备，预留 25 GiB 前完成处理：扩大虚拟磁盘并扩展对应 PV/LV/XFS，或新增数据盘后安排停机迁移。实际扩容前须重新检查 `lsblk`、`findmnt`、`pvs`、`vgs`、`lvs`，备份业务数据。

## 镜像与网络

Coze Studio 以 `0.5.1` 为基线；前端保持官方 Nginx 镜像并只读挂载带 `/agent/` 适配的自建前端产物，后端增加统一账号管理功能，使用本地构建的 `coze-local/server:accounts-二进制摘要前缀`。原始镜像摘要见同目录的核查记录，当前运行镜像及挂载以 `scripts/docker-compose.deploy.json` 和验收记录为准。

基线引用的 `minio/minio:RELEASE.2025-06-13T11-33-47Z-cpuv1` 在部署时已无法从官方 Docker Hub 获取。改用 MinIO 官方 GitHub 发布的对应版本 Linux 二进制，以及官方 mc 二进制，分别核验 GitHub 发布资产的 SHA-256 后，用固定摘要的 Debian 基础镜像封装为 `coze-local/minio:2025-06-13`。服务器 `/home/coze/src/minio-runtime/provenance.json` 记录来源、版本和摘要。该替代保持原有 S3 服务接口，需在验证中检查桶和文件读写。

镜像首次下载期间使用经 SSH 隧道转发的本机代理访问官方仓库；下载完成后移除 Docker 临时代理配置。日常运行不依赖该下载隧道。再次拉取或构建镜像前需确认服务器出网能力。

## 备份

初始化后的数据库元数据每日 03:30 压缩备份到 `/home/coze/backups`，保留最近七份；单次压缩结果超过 5 GiB 或可用空间不足 25 GiB 时失败并记录日志。可手动执行：

```bash
systemctl start coze-backup.service
journalctl -u coze-backup.service -n 20 --no-pager
```

该备份不包含 MinIO 中的上传文件、全部服务配置及完整向量索引，也不是异机容灾。正式投入使用前，应安排对象数据和受限配置文件的异机备份与恢复演练，避免在同一分区保留无限全量副本。
