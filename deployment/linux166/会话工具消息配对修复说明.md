# 会话工具消息配对修复说明

更新日期：2026-11-12。平台入口：`https://ai.yaoxiaoyi.com/agent/`。

## 现象与根因

“通过地址查询医疗机构详情”预览中，输入“浣东街道康福路98号--诸暨市第五人民医院”，部分已有会话返回 `Something error:Internal Server Error`，新建会话有时能返回回答。

对应后端日志显示聊天模型返回 HTTP 400，明确原因是 assistant 消息声明了 `tool_calls`，后续却没有覆盖全部 `tool_call_id` 的工具结果。平台将这个模型请求错误转为前端的通用错误提示。

发现两个相互叠加的问题：一次并行工具事件可能包含多条结果，但原写入逻辑只保存 `ToolsMessage[0]`；历史配对又按同一运行轮次中相关消息数量的奇偶数判断。两个调用及两个结果构成三条消息，本应有效，却可能被奇偶规则误删；两个调用但只存了一个结果构成两条消息，又可能被错误放行。

## 修复内容

| 环节 | 调整 |
| --- | --- |
| 保存工具结果 | 遍历并保存事件中的全部工具结果，每条保留独立的 `tool_call_id`；只有首条复用原预创建的展示消息 |
| 加载历史 | 反序列化后按实际调用 ID 检查紧随其后的工具结果，保留已经配对的调用及结果，不再使用奇偶数规则 |
| 遗留不完整记录 | 只修正发送给模型的历史快照，剔除未配对调用及孤立、重复结果；不伪造结果，不修改或删除原数据库消息 |
| 普通正文 | 保留用户消息和助手正文；跳过空记录、无效 JSON 和 null，避免异常历史引发空指针错误 |

配对仅在同一条 assistant 工具调用后的连续工具结果中进行，不跨越下一条用户或普通助手消息查找结果，不会把其它轮次中重复的调用 ID 错配进来。

本轮未调整真实智能体的人设、模型、知识库绑定、插件授权或记忆轮数；未清空真实会话或重新导入医疗档案。

## 验证方式与结果

1. 在原运行日志中找到多次相同模型协议错误；真实历史中确认存在“声明两个调用、只保存一个工具结果”的记录。
2. 新增 Go 回归测试，覆盖完整和部分完成的并行调用、ID 不匹配、孤立及重复结果、跨轮次边界、无效历史、原对象不被修改，以及全部并行结果分别保存后能再被加载。
3. 使用临时普通账号、临时智能体和合成工具记录复现：原版本同一会话会报错；修复后保留同一组不完整记录即可继续回答。校验原消息摘要不变，记忆轮数保持十轮，验证时总轮数不足十轮，排除清空历史或自然移出记忆窗口造成的假通过。
4. 在用户指定智能体及现有预览上下文中重问原问题，已正常返回业务 JSON，不再出现通用内部错误。当前绑定知识库未找到该名称及门牌片段的明确匹配，业务返回 404；这只表示当前数据未命中，不是对机构真实存在与否的判断。

隔离测试账号、智能体、会话及合成消息已清理。详细结果见 `会话工具消息配对修复验收.json`；原医疗档案保持 19946 行完成、0 失败。接口和浏览器错误消除不等同于知识库外信息已经获得联网权威核验，本轮不把模型生成的机构更名或地址推测作为已核实事实。
