两套模型均不能仅凭这份小样本报告获得生产验收结论。小模型通过预登记的地址筛查门槛，但口语地址指标位于允许下降 5 个百分点的边界。生产继续使用 BGE-M3，没有切换模型或重建索引。

**建议优先完善地址字段筛选，再决定是否迁移轻量向量模型。** 对明确区县或街道的查询，以结构化条件约束范围；向量作为口语表达、地址别称等召回补充；输出前再核对地址条件。

## 样本与执行方法

- 复用此前固定抽取的 500 条真实 Excel 索引记录，以及已经生成的 BGE-M3 / BGE-small 语料向量，不重复编码整份知识。
- 固定种子 `20261112`，构造完整地址、口语地址、街道路段、区县范围各 20 题，共 80 题。用户确认了问法类别，但没有人工逐题标注这 80 题。
- 完整地址和口语地址使用配对记录，因此不应把 80 题视为 80 个相互独立的真实用户查询。完整地址题带省市区县，口语题省略省和区县、保留城市。
- 相关项由真实字段匹配构造：完整地址按同市同区县地址匹配；口语地址按同市地址子串匹配；街道路段按同市同区县地址子串匹配；区县按市及区县字段匹配。
- 评价采用纯向量精确余弦排序，没有把生成标签时使用的字段过滤作为被测算法，也没有用规则匹配自身获得“100%”来证明过滤器效果。
- 仅给新增问题生成向量，主比较不加查询提示词。BGE-M3 使用独立 11435 测试实例，8 核配额、8 线程；生产导入继续运行。小模型使用已有 CPU ONNX 编码器。
- 新增问题最长 43 token，超过 512 token 的为 0 条。测试没有覆盖长篇地址描述或所有错别字、历史地名和地址别称。
- 原问题文本、候选内容和向量只留在服务器受限测试目录；本报告及 JSON 仅包含聚合指标。

## 地址查询的实施建议

1. 优先标准化省、市、区县、街道 / 路段、门牌号等地址字段。保留原始地址，规范全半角、空白和行政区划表达；不能仅因字符串包含“某路”就认定行政上属于同名街道。
2. 对明确行政范围先应用字段约束；同名街道必须结合市、区县，避免仅用地址相似度决定范围。街道路段可以在规范地址上匹配，并按实际业务评估别名规则。
3. 对“列出某区县所有机构”“有多少家”等问题，使用带权限、分页和计数的结构化查询路径；对口语、缺失信息或别称，再用语义召回辅助匹配。
4. 当前源码底层已有 DSL 与 Milvus 的 WithFilter 路径，说明过滤能力可作为扩展基础；本次没有实现从自然语言自动生成这些业务字段条件，也没有调整生产智能体或上线查询接口。
5. 后续验收扩大到全量记录，补充真实用户问法，并包含同名路、跨区县、地址无匹配及需要列出全部结果的负例；再决定轻量模型迁移与相关知识索引重建。

Milvus 官方说明支持在向量检索前使用元数据条件缩小候选范围，参见 [Filtered Search](https://milvus.io/docs/filtered-search.md)。这是建议方案的底层能力依据，本报告没有测量该组合方案的线上效果。
