预览调试模型与知识库配置排障

部署配置、磁盘规划与日常维护操作。容量和验收状态为原文记录的历史快照。

打开平台 下载 Markdown

更新日期：2026-11-11。平台入口：https://ai.yaoxiaoyi.com/agent/。

现象与复现

智能体“通过地址查询医疗机构详情”在预览与调试中输入详细地址后，返回 Something error:Internal Server Error。

复核使用目标账号现有有效会话，通过预览页面实际使用的 POST /agent/api/conversation/chat 接口，以草稿模式重放原问题。接口 HTTP 状态为 200，但回答内容是上述错误文字，不能只检查 HTTP 状态判断成功。

本次浏览器控制连接不可用，因此验收使用同一对话接口，没有宣称已完成浏览器页面的视觉验收。未保存密码、Cookie 或 API Key。

根因

目标草稿选择了模型 100001，属于豆包 / Ark 供应商，其配置不完整。后端模型调用实际返回：

RequestError code: 400
can't fetch endpoint sts token without endpoint

错误发生在智能体模型调用节点，前端显示的是通用 Internal Server Error，并非 Excel 导入失败或知识库向量服务不可用。

进一步检查发现，目标草稿没有绑定任何知识库。仅修复模型选择后虽然可以生成回答，但模型按原人设规则尝试补充推测，未实际使用现有医疗档案。这是另一项配置缺失。

配置修复

通过目标账号有权访问的草稿更新接口修改目标智能体：

  • 智能体 ID：7706717182670929920。
  • 模型从 100001 切换为平台已有可用的 100002，显示名称为 DeepSeek Flash。
  • 绑定现有“浙江省医疗档案”知识库，ID 为 7706718830218706944。
  • 将知识库检索设置为自动检索，使用户直接输入地址时能够先读取绑定知识。

原人设、唯一 JSON 回复要求、知识库 Top-k / 阈值及其它检索选项保持原有配置。更新模型时平台按所选模型规则保存其支持的参数，以保存后的配置为准。

本次属于草稿配置修复，没有修改平台业务源码、替换模型凭据、重建向量或重新导入文件，也没有执行发布。发布版本若需使用这些设置，应在草稿验收后按正常流程发布。

验证动作与结果

  1. 修改前重放原始详细地址，复现同样的错误；日志定位到 Ark 缺少 endpoint。
  2. 切换至 DeepSeek 后，对话恢复，但未绑定知识导致回答来自模型推测，不能将这一阶段视为检索修复完成。
  3. 绑定现有知识并启用自动检索后，重放带括号备注的原始地址，约 9.7 秒返回成功 JSON，机构名称为“鹿城区上戍乡社区卫生服务中心”。
  4. 使用不带括号备注、明确询问对应医疗机构详情的问法回归，约 7.8 秒返回同一机构，无通用错误。
  5. 只读核对原始知识表，确认该机构及地址来自现有数据；同一门牌还出现在另一机构的复合地址中。回归回答按原人设的唯一结果要求选择了地址更直接匹配的记录。

耗时来自两次单次实际对话，包含公网和模型生成时间，不代表并发性能承诺。原始表格没有机构标识和机构编码字段，回答将这两个字段留空，不能用内部切片编号冒充业务编码。

排除的方向与使用提示

  • 不应通过重新上传 Excel 或重建向量解决本次错误：日志指向聊天模型配置，原知识已处理完成。
  • 不应仅凭“已经能生成回答”判断知识库检索成功：还需检查是否实际绑定知识，并与原始记录核对。
  • 新建智能体时应选择已配置完整的模型，在智能体内实际添加知识库；上传知识文件不会自动绑定到所有智能体。
  • 设置更新后刷新编辑页再调试，避免页面仍显示修改前的模型或知识配置。

本次用户补充了具体智能体、原始地址问法和错误文字，要求复现真实预览场景；修复以该场景和一条相邻问法回归为准。
