Coze Studio 公网 /agent/ 子路径访问与运维

部署配置、磁盘规划与日常维护操作。容量和验收状态为原文记录的历史快照。

更新日期：2026-11-10。服务器：ssh linux166。基线：v0.5.1，保留统一账号管理扩展。

正式入口

平台入口为 https://ai.yaoxiaoyi.com/agent/。

主平台 https://ai.yaoxiaoyi.com/agent/
登录 https://ai.yaoxiaoyi.com/agent/sign

API 调用者使用平台自身的 API Token。模型厂商的 Base URL 保持厂商提供的地址，/agent/ 是本平台的访问前缀。

内网 http://192.168.1.166:8888/ 仍可访问，已执行浏览器回归。域名根路径继续保留原服务的认证行为。

原因与适配方式

原页面虽然能从 /agent/ 返回，但脚本、API 和页面导航使用 /static/、/api/、/sign 等根路径。这些请求进入域名根路径的其他服务，返回带 Basic realm="zw" 的 HTTP 401 响应，从而触发浏览器认证弹窗。

本次适配包含三层：

  1. 外层 Nginx 接收 /agent/，去除前缀后转发166，同时传递外部协议、Host 和 X-Forwarded-Prefix。外层配置由用户更新。
  2. 前端构建把静态资源前缀设置为 /agent/。React Router 根据当前浏览器路径选择 /agent 或根路径作为 basename。
  3. 页面入口加载 app-base-path.js，为同站的 Fetch、XHR、EventSource、WebSocket、历史记录及新窗口地址补齐前缀。已经包含前缀的地址保持不变，第三方地址保持不变。

后台静态页面同样加载入口脚本，样式和管理脚本使用相对地址。登录跳转、整页刷新、新建智能体和知识库时使用的新窗口地址也进行了适配。

166 的内层 Nginx 支持 /agent/ 的内部重写，并按外层传入的协议和前缀处理 Cookie、重定向以及 MinIO 文件地址。公开访问时，登录 Cookie 的 Path 为 /agent/。

后续构建

将需发布的源码同步到独立构建副本后，可在166运行以下脚本执行专项测试和前端构建，复用该目录已经安装的依赖，默认只生成产物：

bash /home/coze/ops/build-agent-web.sh /home/coze/build/subpath-source

构建产物位于源码目录的 frontend/apps/coze-studio/dist。脚本限制并发和 Node 内存目标，不会自动重启平台。发布时应复制产物到新的版本目录，更新 Compose 中 coze-web 的只读挂载，然后只重建前端容器：

/home/coze/ops/compose.sh up -d --no-deps coze-web
docker exec coze-web nginx -t

部署不能只复制单个页面脚本，应发布完整的 dist，同步本仓库的后台入口文件和内层 Nginx 配置，避免版本不匹配。

本次未运行整个仓库的全量测试，也未使用真实模型发起付费推理。流式连接和 WebSocket 的测试覆盖地址映射与参数保留，不代表已完成所有外部工具或模型链路的端到端验收。

回退

本次发布前备份了 Compose、内层 Nginx 及后台静态文件。目录记录在 /home/coze/ops/subpath-backup-path，具体备份位于 /home/coze/backups/subpath-时间戳。

由运维核对目录后，将 compose.json、nginx.conf 和 admin 内容分别恢复到原运行位置，再执行：

/home/coze/ops/compose.sh up -d --no-deps coze-web
docker exec coze-web nginx -t

回退不恢复数据库，以保留发布后的业务数据。回到原前端后，公网 /agent/ 适配将失效，因此此操作仅用于应急。
