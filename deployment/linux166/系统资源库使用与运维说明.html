系统资源库使用与运维说明

部署配置、磁盘规划与日常维护操作。容量和验收状态为原文记录的历史快照。

打开平台 下载 Markdown

更新日期：2026-11-14。适用于本仓库的 Coze Studio 定制版本。

平台入口：https://ai.yaoxiaoyi.com/agent/。普通用户进入工作空间左侧的“资源库-系统”；管理员进入 /agent/admin/#system-library 的“系统资源发布”。

功能与共享方式

系统资源库只展示平台提供、经维护者预览调试确认可直接使用、无需厂商额外授权的插件、工作流、提示词、知识库、数据库。普通用户可以搜索、按类型筛选、分页和查看使用说明，不提供创建、编辑、删除系统原件的入口。系统资源使用原资源 ID 共享引用，不为每个用户复制一份。

添加插件窗口同时保留两个独立入口：“搜索工具”提供原有第三方工具；“资源库-系统”只提供平台发布的系统插件。二者使用不同接口与数据来源，系统目录不再自动读入第三方工具。即使管理员已为高德地图等工具配置共用密钥，这些工具仍属于“搜索工具”，不因此成为免额外授权的系统资源。

类型 使用方式 更新行为与限制
插件 智能体或工作流的插件选择窗口选择独立的“资源库-系统”入口 平台开发、完成调试并发布的工具，无需用户另行申请 API Key 或 OAuth 授权
工作流 工作流选择窗口选择“资源库-系统”，也可用于任务中心 普通引用执行管理员当前公开版本；任务中心保留任务创建时固定的已公开版本
提示词 提示词库中选择“资源库-系统”，或从详情复制内容 公开发布时的内容快照；可修改自己编辑器中的内容，不能修改系统原件
知识库 添加知识库窗口切换“资源库-系统” 引用同一个知识库，查询源数据的最新可用内容，普通用户不能上传、改切片或删除原件
数据库 添加数据库窗口切换“资源库-系统” 同一张公共表只读查询，不能修改表结构或数据；SQL 限制为当前授权逻辑表的 SELECT

所有已发布系统资源对平台上的所有登录用户、所有空间和项目开放。用户自己的资源仍保留原有权限，不会因为新增此模块自动公开。原有未发布的工作流示例模板继续沿用原模板流程，不自动成为可执行的系统资源。

管理员开发与发布

  1. 使用管理员账号在自己的资源库开发、维护资源。应用或项目内部的资源应先移入资源库，防止删除应用时级联删除系统资源原件。
  2. 工作流先保存并发布一个有效版本；插件先完成工具调试和原生插件发布，认证类型必须为无需认证。知识库须已有文档且全部处理完成，数据库先准备好公共查询数据。工作流依赖的插件、子工作流、知识库或数据库须先发布为系统资源。
  3. 打开后台“系统资源发布”，选择类型，粘贴资源 ID 或详情页地址，点击“读取并预览”。详情地址仅在浏览器提取 ID，不由服务端访问该地址。
  4. 核对资源名称、版本和使用说明。同时确认“资源及数据可向全平台用户公开共享”和“已完成预览调试、资源及全部依赖可直接使用且无需厂商额外授权”，两项均勾选后才允许发布。
  5. 普通用户刷新“资源库-系统”或相应资源选择窗口即可使用。不会移动原件，也不会自动修改已有智能体的绑定。

发布源限当前管理员本人维护、位于资源库的资源；平台原生内置资源另行识别。普通账号即使直接调用后台发布接口也无权发布。发布与下架带修订号检查，并发操作冲突后需要刷新重试。

原搜索工具目录中的插件不能直接发布为系统资源。自建插件若声明 API Key、服务令牌、OAuth 等认证方式，服务端同样拒绝发布。维护者须验证实际可用性及全部运行依赖；静态认证类型检查不能代替对任意 HTTP 接口、脚本业务逻辑、网络和平台模型配置的真实调试。

发布知识库、数据库意味着其中数据向全平台用户开放查询，请在确认前完成数据范围核对。目录元数据不包含插件凭据、数据库连接串和请求默认值；共享知识库文档列表不向非所有者返回 API 数据源地址。

更新、下架与已有引用

维护完成后在后台重新预览并更新发布。工作流的源草稿保存不会直接公开给其他用户；先原生发布版本，再更新系统资源发布记录。提示词同样需要重新发布才更新公开内容快照。

知识库和数据库共享源数据，源数据变化会影响后续查询。插件按原生已发布工具执行，变更参数前应核对已有引用。工作流的输入输出结构、数据库字段等变更也应先验证兼容性。

下架保留源资源和发布历史，普通目录隐藏该资源，旧共享引用在读取或执行时不再具有公共授权。用户已插入自己编辑器的提示词文本属于自己的内容，不会远程撤回。重新发布可以恢复共享。

源所有者仍为管理员时，可以在下架期间调试插件原件。普通共享调用只执行已发布工具，不会使用管理员尚未发布的插件草稿。

系统原件的维护还要求源所有者仍具有管理员身份。账号降为普通用户后，不能继续维护其已发布的系统原件；恢复管理员或实施经过审查的资源归属迁移后再维护。

数据库与执行权限

公共数据库在选择列表、绑定智能体和查询阶段均按只读处理。服务端拒绝公共表的新增、更新和删除；工作流 SQL 查询逐个检查语法树中的表名，拒绝跨表、跨库、写入、多语句、文件导出、加锁、会话变量及不支持的函数。公共数据查询不会再按引用者的用户 ID 隔离，以便所有用户读取已明确公开的数据。

系统资源由平台统一提供运行能力，不要求使用者为资源另行申请厂商授权。平台已有的模型、Embedding、网络等服务配置仍由运维维护。需要厂商授权的第三方工具继续在“搜索工具”中选择和配置，不混入系统目录。调整目录来源不删除第三方插件、不清除已有密钥，也不更改用户已有智能体的工具绑定。

数据表与部署

新增独立表 system_resource_publications 和 system_resource_releases，分别保存当前公开状态与修订历史。源资源仍保存在原有领域数据表，不复制知识数据或数据库记录。

迁移脚本为 deployment/linux166/scripts/system-library-schema.sql。发布前先执行两条 CREATE TABLE IF NOT EXISTS；应用启动仅检查表是否存在，不自动执行 DDL。没有完成迁移时，发布接口不应作为可用服务开放。

发布产物、构建缓存、备份继续使用 /home/coze。部署前运行 /home/coze/ops/capacity.py --guard；根分区至少保留 15 GiB，/home 至少保留 25 GiB，并遵循现有使用率守卫。服务重建前确认知识库消息队列及任务中心没有正在运行的作业。

单项公开元数据最大 512 KiB；登记最多 5000 项；当前元数据与修订历史合计上限 256 MiB。配额只约束系统资源元数据，不代表知识库、数据库、模型、日志和 Docker 镜像总空间。历史不自动删除，达到配额时由管理员按保留要求先归档。

必须保留现有 /agent/ 路径适配、Nginx 启动配置、插件凭据密钥只读挂载和 Embedding 工作进程配置。新增模块不要求更换向量模型、维度或重建已有知识索引。

备份、回退与故障排查

沿用 /home/coze/ops/backup.py 的元数据库与插件凭据密钥配对备份。部署另备份 Compose 和本次涉及的后台静态文件。回退到旧镜像、旧前端目录及旧后台文件时保留新增发布表，不用旧数据库覆盖部署后产生的用户数据。

现象 检查位置
后台不能预览资源 类型与 ID 是否正确、当前管理员是否为源所有者、资源是否位于资源库、插件或工作流是否完成原生发布
普通目录看不到资源 是否已发布为系统资源，是否被下架，类型与搜索条件是否正确
共享工作流没有更新 是否先发布源工作流新版本并更新系统发布记录；任务中心是否固定旧版本
系统插件调用失败 先检查平台服务、工具入参和维护者调试记录；如依赖额外厂商授权，应下架并修正资源，不让普通用户补授权
数据库查询被拒绝 是否使用当前逻辑表的只读查询，是否包含跨表、写入或不支持的函数
发布提示修订冲突 刷新并重新预览，避免覆盖另一个维护操作
发布提示容量不足 核对元数据大小、登记数量、历史配额及磁盘容量；先归档，不盲目删除业务数据

专项验收结果见同目录的 系统资源库验收.json，部署及运行核对见 系统资源库运行核对.json。验收仅使用合成资源与临时账号，不将客户已有知识库发布为系统资源。完整仓库测试与所有第三方服务联调不包含在专项验收范围内。

本次验收结果

2026-11-14 已按独立双入口及无需额外授权的定义调整并部署，71 项跨账号 API 与页面检查通过。专项验收包括五类资源发布、两个普通用户跨空间选择、四个智能体引用同一公共数据库、实际工作流执行、更新修订、任务中心固定版本、只读接口拦截、下架历史、发布准入、两个插件选择入口、系统插件实际绑定及数据来源分离。原有厂商授权配置摘要核对一致。具体执行结果与时间见专项验收 JSON。数据库 SQL 隔离、目录筛选分页、工作流依赖检查单元测试，以及前后端构建和文档布局核对均通过。

平台原有 6 个本地提示词保留在系统目录。原有 18 个第三方插件保留在“搜索工具”，不占用系统资源数量。系统插件、工作流、知识库、数据库由平台后续开发、完成调试并明确发布后展示；不放入未经验证的示例占位资源。合成验收资源和临时账号在验收结束后清理。

11 个容器运行正常，两份既有知识数据分别保留 19,946 行和 9,000 行，均处理完成。双 Embedding 工作进程及插件凭据只读挂载保持正常。运行核对时根分区剩余约 67 GiB，/home 剩余约 82 GiB，精确数值及时间见运行核对记录。原客户账号会话已过期，本次未重新登录该真实账号，因此原地址查询未作登录态 API 复测；已独立核对原知识数据完整性。
