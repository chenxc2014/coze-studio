结论

目标智能体“通过地址查询医疗机构详情”确实绑定了天眼查和高德地图的工具，两者都能被聊天模型实际调起，但当前均未取得成功的业务数据。运行服务器上的两项内置插件 service_token 都为空；插件被添加到智能体，不代表第三方服务授权已经配置。

实际调用结果

使用目标账号现有有效会话，通过该智能体实际预览对话接口分别发起两次只读工具验证。检查依据是持久化的 function_call 和 tool_response 消息，不能只根据模型生成的回答认定工具执行成功。

插件 实际选择的工具 工具原始返回 当前结果
天眼查 abnormal_operation，企业经营异常查询 error_code=300008，reason=缺少必要参数 业务调用失败；授权 Token 为空，需补齐有效授权后继续核验参数和接口权限
高德地图 placeAround，周边搜索 status=0，info=INVALID_USER_KEY，infocode=10001 授权失败；当前没有取得周边地点数据

两次对话总耗时分别约 26.8 秒和 28.2 秒，包含模型生成、知识检索和工具调用，不能当作第三方接口自身耗时。两次 HTTP 状态都是 200，但工具业务状态失败。

天眼查测试包含公司全称和分页参数，高德测试包含合法格式的经纬度、搜索半径和地点类型。测试仅查询公开业务数据，没有申请凭据、修改插件设置或变更智能体绑定。

当前场景的能力缺口

  • 天眼查目前只勾选了经营异常查询，没有勾选企业搜索或企业基本信息查询。这个工具无法独立完成“按地址定位机构并读取机构详情”。
  • 高德目前只勾选了周边搜索，必填参数为经纬度 location。中文地址不能直接作为这个参数；若要支持地址输入后的查询链路，应按实际需求补选地理编码、地点搜索等工具。
  • 智能体原人设还提到“火山联网问答”，当前实际绑定列表没有这个插件，不能认为人设中提到的所有能力都会自动可用。

后续配置与边界

天眼查需要有效的开放平台授权 Token，以及所调用接口的可用权限；高德需要有效的 Web 服务 API Key。聊天模型的 API Key 和这两家插件的授权互不替代。

当前两项内置插件来自运行配置 backend/conf/plugin/pluginproduct/plugin_meta.yaml，通过服务认证配置向天眼查请求头、高德请求查询参数注入授权。该文件包含所有内置插件元数据；日后配置真实凭据时应保留服务器私有副本和备份，禁止将密钥提交到 Git。源码中保留空值模板。

本次没有获得可用的插件凭据，因此没有宣称修复成功。补齐授权、确认第三方权限并调整必要工具后，应再次通过这个智能体的真实预览对话验证，并核对原始工具返回。
