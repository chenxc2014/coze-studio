# 重启后登录页出现认证弹窗的原因与修复

更新日期：2026-11-11。正式入口：`https://ai.yaoxiaoyi.com/agent/`。

## 故障原因

扩容重启后，Docker 给后端容器重新分配了地址：实际地址为 `172.18.0.12`，前端 Nginx 却仍向旧地址 `172.18.0.4:8888` 转发。日志确认 `/admin/app-base-path.js` 和账号接口均因此返回 502。

登录页面 HTML 和样式由前端正常提供，所以仍能看见登录表单。但关键的路径适配脚本当时依赖后端提供；脚本加载失败后，页面发起了不带 `/agent/` 的 `/api/passport/account/info/v2/` 请求。

同一域名的根路径由另一个服务处理，响应包含 `WWW-Authenticate: Bearer realm="zw", Basic realm="zw"`。浏览器因此弹出 HTTP Basic 认证框。这不是 Windows 或 Linux 系统账号登录，也不应在这里输入服务器账号。

## 已实施修复

1. Nginx 使用 Docker DNS `127.0.0.11`，缓存有效期 10 秒。后端和 MinIO 上游通过变量代理，容器地址变化后重新解析。
2. `/admin/app-base-path.js` 改由前端 Nginx 从只读挂载文件直接提供，不再依赖后端接口是否可用。外层 `/agent/` 前缀访问和内网根路径均兼容。
3. linux166 运行 Compose、默认 Compose 和 OceanBase Compose 均补充该公共脚本挂载，保持配置一致。

没有取消根路径服务原有的身份验证，也没有在代理上吞掉所有 401 响应。Coze 未登录账号接口返回其自身的 401 是正常行为，关键是响应不含 Basic 认证挑战。

## 验证结果

- 正式地址匿名登录页检查：没有逃逸到根路径的请求，没有认证挑战，没有页面脚本错误。
- 原账号知识页面检查：正常显示“浙江省医疗档案”，不再显示旧的数组越界错误，没有认证弹窗。
- 后端重建后保持前端 Nginx 运行，验证接口依靠动态 DNS 恢复，不依赖人工重新加载 Nginx。
- 独立回归容器中将后端指向不可用地址：登录页面和路径脚本仍为 200，账号接口为 502，未附带认证挑战；测试后容器已移除。

原配置备份目录记录在 `/home/coze/ops/nginx-reboot-backup-path`。当前 Compose 和 Nginx 源码均保存在仓库中。

## 用户操作

关闭原有认证弹窗，按 `Ctrl+F5` 刷新页面，然后在药销易平台自己的登录表单中使用平台账号登录。如果以后再次出现类似弹窗，应检查具体失败请求的地址与 `WWW-Authenticate` 响应头，不应直接取消其他服务的认证。
