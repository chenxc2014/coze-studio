已实施结果

双进程向量编码已上线。两个独立 Ollama 进程各使用 8 个推理线程，通过 Go 连接池并行处理同一份文档的两个编码批次；结果按输入顺序汇总，再交给原有写库、索引和断点流程。

连接池启用范围与一致性

当前运行 Compose 的 coze-server.environment 增加：

OLLAMA_EMBEDDING_WORKER_URLS=http://172.18.0.1:11439,http://172.18.0.1:11440
OLLAMA_EMBEDDING_POOL_BASE_URL=http://172.18.0.1:11434
OLLAMA_EMBEDDING_POOL_MODEL=bge-m3-cpu

只有知识库配置同时匹配上述 Base URL、模型名称，且已经明确向量维度时，才启用连接池。后台选择其他模型、修改 Base URL 或选择其他供应商，继续按原设置调用；自动探测维度也保留原入口。未设置工作进程列表时保持原串行行为。

连接池优先分配空闲进程，所有共享该连接池的调用合计最多占用两个进程，每个进程同时只执行一个编码请求；每次调用最多创建两个编码协程。较短批次可以继续由空闲进程处理，不强制排到另一进程的慢批次后面。

每个批次写入结果数组的原始位置。只有所有批次均返回正确数量、正确维度且数值有限的向量，才向上层返回完整结果，防止乱序向量对应到错误机构。

一个进程调用失败时，在另一个进程补试一次；两个进程都失败，则整次编码返回错误和空结果，不把部分向量交给上层。原有 NSQ 重试和在途分段 ID 继续生效，当前文档批次的完成断点不会因为部分编码成功而提前推进。数据库、ES、Milvus 的既有处理流程未改为多个独立写入任务，也未新增跨存储事务保证。

取消请求会终止等待和在途请求并释放进程。更换模型权重时必须同时维护工作进程中的模型清单，并重新评估既有向量兼容性；相同的模型名称或维度不代表不同权重的向量可以混用。
